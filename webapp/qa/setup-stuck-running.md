# セットアップWebアプリのステップが「実行中」のまま進まない

- 症状: あるステップを実行すると、ログが止まったまま「実行中」の表示が
  いつまで経っても変わらない
- 機種/日付: cube-petit-yellow、2026-07-17(実機で2件発生・両方とも修正済み)

## 原因

今のバージョンでは自動対処済みですが、これまで実機で実際に2種類の
「無言でハングする」原因が見つかっています。

1. **ENTER待ち**: 「④ROS2導入」ステップ内の `add-apt-repository universe`
   に `-y` が付いておらず、対話的に「Press [ENTER] to continue」と聞いて
   きていました。Webアプリ経由で実行するとこの入力待ちが画面に出ず、
   ステップがいつまでも終わらないように見えていました
2. **シリアルopenブロック**: 「⑧センサ接続確認」でLiDAR/IMUの状態を見る
   `stty` が、`clocal` オプションなしでシリアルポートを開くとキャリア
   検出待ちで**開く時点で**無限に止まることがありました。既存の
   `timeout` は後段の `cat` にしか掛かっておらず、そこに到達する前に
   固まるため無力でした

## 対処

**現行バージョンでは両方とも修正済みです**(`add-apt-repository -y` 化、
Webアプリのエンジンが子プロセスに端末を継承させない、`stty` 自体に
`timeout` と `clocal` を付与)。最新版に更新してから実行すれば発生しません。

古い版や、上記以外の理由で「実行中」のまま固まってしまった場合の
一般的な対処:

```bash
# 1. run.shを一度止めて再起動する(Ctrl+Cで停止 → 再度起動)
cd ~/work/cube_petit_setup/webapp
./run.sh

# 2. ブラウザを再読み込みし、固まっていたステップの
#    「もう一度実行」を押す(全ステップは繰り返し実行しても安全な設計)
```

それでも直らない場合は、リポジトリを最新化してから試してください。

```bash
cd ~/work/cube_petit_setup
git pull --ff-only
```
