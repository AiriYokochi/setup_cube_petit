# PR(Pull Request)の出し方

featureブランチをpushしたら、メインライン宛のPRを作ります。
(定型の手順・体裁は `.claude/skills/new-pr/SKILL.md` にもあります。自分の
チーム・リポジトリに合わせて調整して使ってください)

## タイトル

- 「何がどう変わるか」が一覧で分かるように書きます
- 悪い例: 「修正」「update」 / 良い例: 「IMUのudevルールがCANable2にマッチしない問題を修正」

## 本文に書くこと

1. **概要** — なぜこの変更が必要か(背景・症状)
2. **変更内容** — 何をどう変えたか(箇条書き)
3. **確認方法** — どうやって動作確認したか/レビュアーがどう確認できるか
4. **実機テストの要否** — 実機でしか確認できない変更は**その旨を明記**し、
   未実施ならテスト手順を書きます(ラベルやチェックボックスの運用があれば従う)

## マナー

- 1 PR = 1 目的。無関係な変更を混ぜません
- エラーログ・スクリーンショットは要約せず生のまま貼ります(長ければ折りたたみ)
- レビュー指摘への修正は同じブランチに追いコミットします(force-pushで歴史を
  書き換えない。レビュー差分が追えなくなるため)
- マージ後はブランチを削除します([branch_rules.md](branch_rules.md))
