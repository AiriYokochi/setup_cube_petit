# 個体固有の情報の扱い

CubePetitは複数の個体が同じソフトウェアを共有します。**「この個体だけの値」を
共有リポジトリに直接書き込まない**のが原則です。

## 個体固有の情報の例

- 個体名(robot_namespace。例: `cube_petit_{{ROBOT_NAME}}`)とホスト名
- `ROS_DOMAIN_ID`(複数台を同じ場所で動かすときに個体ごとに変える値)
- センサのキャリブレーション値・取り付けオフセット
- ネットワーク設定(Wi-FiのSSID、固定IPなど)
- APIキーなどの秘密情報(**これはgitにはどこにも入れない**。~/.bashrc 等の
  ローカルファイルだけに置く)

## どこに書くか

| 情報 | 置き場所 |
|---|---|
| 環境変数(ROS_DOMAIN_IDなど) | `~/.bashrc`(セットアップアプリの「環境設定」ステップが管理) |
| 個体の記録・測定値・調整履歴 | このワークスペースの `docs/` に個体の記録として残す |
| 全個体に共通の修正 | 共有リポジトリにfeatureブランチ+PR([branch_rules.md](branch_rules.md)) |

## 見分け方

共有リポジトリに書こうとしている値について「他の個体でもこの値で正しいか?」と
自問してください。答えがNOなら個体固有です。launch引数(`robot_namespace` など)や
環境変数で外から渡す形にして、値そのものはこのワークスペースか機体のローカル設定に
置きます。
